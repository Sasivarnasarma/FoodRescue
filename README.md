# FoodRescue

FoodRescue is an Android-first university project that connects businesses with nearby verified organizations for free surplus-food donations. Smart matching prioritizes time-sensitive listings and compares requests by distance and pickup feasibility.

## Repository structure

```text
FoodRescue/
├── AGENTS.md
├── README.md
├── docs/                 # Product, architecture, data, security and delivery docs
├── mobile/               # Expo + React Native + TypeScript Android app
├── admin/                # React + TypeScript web admin dashboard
└── firebase/             # Firestore rules/indexes, Storage rules and Firebase config
```

## Approved technical decisions

- Mobile: React Native + Expo + TypeScript
- Initial platform: Android
- Admin: separate React + TypeScript web app
- Backend: Firebase
- Database: Cloud Firestore
- Authentication: Firebase Authentication
- Listing photos: one optional compressed JPEG stored as Firestore bytes on Spark. Firebase Storage remains planned for future file storage
- Updates: in-app Firestore activity and optional local Expo reminders; automated remote push deferred
- Donation: one approved organization takes the whole listing for free
- Demo: two Android phones share Firestore updates and complete QR pickup, with verification on the separate admin site

See `docs/03_TECHNICAL_SPECIFICATION.md` for the stack and [MVP decisions and no-billing scope](docs/15_MVP_DECISIONS_AND_FREE_TIER.md) for resolved workflows, current Firebase constraints and sources. The free demo supports one compressed listing photo, a labelled sample fallback, synthetic verification review, and authenticated two-party QR reference pickup.

## Getting started

This documentation pack does not contain a configured Firebase project or application source code yet. First create the Firebase project and the two app workspaces.

### Suggested setup sequence

1. Confirm the Firestore region and create a Spark Firebase project without billing.
2. Enable email/password Authentication; securely provision the first admin claim through an authorized local operator.
3. Create a Cloud Firestore database and choose the appropriate region with the team.
4. Keep hosted Storage disabled and Storage rules deny-all; do not enable billing or deploy Functions. Use Firestore for compressed listing photos.
5. Register the required Firebase clients. Configure both Android phones and the admin app to connect to the same project.
6. Create the Expo mobile app in `mobile/`.
7. Create the React + TypeScript admin web app in `admin/`.
8. Configure environment variables using `.env.example` files; never commit real values.
9. Review and test the rules in `firebase/` before using real user data.

### Suggested commands (run from the relevant folder)

Mobile starter command reference (do not run into the existing nonempty folder without preserving its environment example and inspecting starter behavior):

```bash
npx create-expo-app@latest mobile
```

Admin starter command reference (preserve the existing environment example and inspect starter behavior before scaffolding):

```bash
npm create vite@latest admin -- --template react-ts
```

Install and run commands depend on the package files generated by the selected starter. Check the current Expo and Firebase documentation before choosing native packages or build commands.
